# SIM-карта на OnePlus 6T

## Карта, вставленная при работающем телефоне

Модем (QMI) видит карту и приложение USIM, читает ICCID, но не открывает
основную сессию подготовки: `qmicli --uim-get-card-status` показывает
`Primary GW: session doesn't exist`, `PIN1 state: 'not-initialized'`, а
ModemManager остаётся в `failed`, `sim-missing`. Перезапуск ModemManager и
перевключение питания слота не помогают. Помогает открыть сессию вручную:

    qmicli -p -d qrtr://0 --uim-change-provisioning-session="session-type=primary-gw-provisioning,activate=yes,slot=1,aid=<AID USIM>"
    systemctl restart ModemManager

После этого ModemManager видит `lock: sim-pin`. С 11.10.2026 это делает
служба `alt-sim-slots` по событиям модема (см. раздел «Подхват по событиям»),
раньше `alt-sim-hotplug` опрашивала `sim-missing` раз в 3-10 секунд.

## Запрос PIN-кода

На запертой карте раньше выходили два окна plasma-nm на старых виджетах Qt,
вне темы и без экранной клавиатуры. Первое («Вход в mts») выводил агент
секретов: NetworkManager поднимал `mts` сам, уходил в `need-auth` и просил
PIN. Второе («Требуется разблокирование PIN-код SIM-карты») выводил
следильщик модема в kded plasma-nm, в том числе на `sim-pin2`, которое
модем сообщает уже после разблокировки. Модуль «Сотовая сеть»
(`kcm_cellular_network`) запертый модем не видит вовсе.

Как устроено теперь (проверено 27.09.2026):

- `alt-sim-unlock` открывает окно `sim-unlock/main.qml` в стиле настроек
  (FormCard, цифровая клавиатура). Код уходит прямо в ModemManager
  (`Sim.SendPin`, после трёх ошибок `Sim.SendPuk` с новым PIN), окно
  показывает остаток попыток.
- `alt-sim-pin-notify` (служба пользователя) открывает окно, как только
  находит запертую карту. Если окно закрыли кнопкой «Позже», висит
  уведомление с кнопкой «Разблокировать».
- `50-alt-mobile-sim.rules` разрешает вводить PIN без пароля пользователя
  (по умолчанию у ModemManager `auth_self_keep`).
- У `mts` выключено автоподключение. Подключение поднимает
  `alt-sim-hotplug`, когда модем зарегистрировался в сети.
- В `~/.config/plasma-nm` стоит `UnlockModemOnDetection=false`, это
  выключает окно следильщика модема.

Модуль QML DBus из Plasma (`org.kde.plasma.workspace.dbus`) ждёт сигнатуру
в скобках, `(s)`. С голой `s` аргументы теряются и модем отвечает
`type of message, "()", does not match expected type "(s)"`.

Установка: `install.sh` от root.

## Второй телефон, 11.10.2026

- Карта во **втором** гнезде лотка: скрипт подхвата искал её только в слоте 1.
  Теперь слот берётся из `--uim-get-card-status`. Но и тогда PIN из слота 2 не
  проходит: `couldn't verify PIN: QMI protocol error (3) 'internal'` (попытки
  не тратятся), ModemManager, видимо, проверяет PIN через DMS, а та знает только
  слот 1. Решено переназначением: модем работает с одним физическим гнездом
  как с логическим слотом 1, после `qmicli --uim-switch-slot=2` PIN из второго
  гнезда прошёл и модем вышел в сеть. Теперь это делает `alt-sim-slots.py`.
- `mmcli` 1.24 раскрашивает вывод и в канал: `grep "failed reason: sim-missing"`
  не находил; проверки переведены на `mmcli -K`.
- Окно PIN запускает `qml-qt6` из `qt6-declarative-devel`; без пакета вместо
  нашего окна было системное. `install.sh` ставит пакет.
- `UnlockModemOnDetection=false` в `~/.config/plasma-nm` обязателен, иначе
  второе, системное окно PIN (настройка пользователя, переносить вручную).
- Окно: значки «стереть» и «готово» цвета текста (галочка терялась на тёмном),
  цифры по касанию, а не по отпусканию. Уведомление только после «Позже».
- Скорость: служба уведомлений реагирует на сигналы ModemManager, скрипт
  подхвата опрашивает раз в 3 секунды (окно PIN было через 45 секунд).

## Подхват по событиям, 11.10.2026

Замер на втором телефоне: окно PIN через 35-45 секунд после вставки карты.
Откуда это бралось (журнал ModemManager с `mmcli -G DEBUG`):

- Модем шлёт индикацию UIM «Slot Status» сразу при вставке и извлечении
  (лоток задвинули, через доли секунды индикация), ICCID читается и в
  неактивном гнезде. Пустое гнездо лотка (проверено: в нём ничего нет) через
  4 секунды после того, как задвинули лоток, показывается `present` с ICCID
  `unknown`, видимо, датчик гнезда срабатывает на сам лоток. Такое гнездо не
  выбираем, верить можно только ICCID.
- ModemManager сам ловит эти индикации (SIM hot swap у `qcom-soc` включён):
  при изменении активного гнезда пересоздаёт модем, при изменении неактивного
  только обновляет объект SIM. Но на вставленную на ходу карту модем не
  открывает сессию USIM, и ModemManager 30 раз через 2 секунды получает «GW
  primary session index unknown» (в журнале «No card found (retry)»), потом
  `failed`, `sim-missing`.
- Пересоздание модема ждало ещё 5 + 10 + 10 секунд: модем на запросы PDC
  «List Configs» и LOC «Get Server», «Get Predicted Orbits Data Source»
  присылает индикацию с ответом раньше подтверждения запроса, а ModemManager
  подписывается на индикацию только после подтверждения и теряет её. Это
  ошибка ModemManager (есть и в основной ветке на 04.10.2026), исправлено
  патчем `packages/ModemManager/0001-qmi-listen-for-indications-before-sending-request.patch`.

`alt-sim-slots.py` (служба от root) слушает `qmicli --uim-monitor-slot-status`
и на каждое событие: если в активном гнезде нет читаемой карты, а в другом
есть, переключает гнездо (`--uim-switch-slot`); затем ждёт приложение USIM в
состоянии карты и открывает сессию. ModemManager находит карту на ближайшем
переспросе, без перезапуска. Перезапуск ModemManager только запасной путь,
если он уже сдался (`sim-missing` при открытой сессии).
`alt-sim-hotplug.sh` остался для мобильного интернета и GPS.
