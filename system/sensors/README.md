# Датчики OnePlus 6T (акселерометр, освещённость, приближение)

Датчики подключены к процессору SLPI и доступны только через QMI-службу
SSC. Проверено 27.09.2026.

- `hexagonrpcd` (Sisyphus) отдаёт процессору датчиков файлы реестра и
  библиотеки. Файлы уже вынул droid-juicer при установке ALT Mobile в
  `/var/lib/droid-juicer/sensors/` (dsp/sdsp 21 файл, sensors/config 55,
  sensors/registry 277, со своего раздела persist). Служба
  `hexagonrpcd-sdsp` была выключена, теперь включена.
- `libssc` (Sisyphus) с утилитой `ssccli`: акселерометр, освещённость,
  приближение и магнитометр отвечают; «компас» (виртуальный датчик) нет.
  Магнитометр даёт ~100 мкТл при земных ~50, не откалиброван.
- `iio-sensor-proxy` в Sisyphus собран без SSC (ALT bug 59720). Пересобран
  `3.9-alt1.1` с `--enable ssc_support` (`packages/iio-sensor-proxy`).
- `81-alt-mobile-sensors.rules`: upstream включает через SSC только свет и
  компас, акселерометр и приближение добавлены; матрица ориентации
  акселерометра `-1,0,0; 0,-1,0; 0,0,-1`. Правило postmarketOS для fajita
  (`0,1,0` во второй строке) при нашем реестре переворачивало экран вверх
  ногами. Автоповорот проверен пользователем во всех положениях.
- Drop-in `iio-sensor-proxy.service.d/ssc.conf`: запуск после
  hexagonrpcd и доступ к `AF_QIPCRTR`.

Журнал hexagonrpcd засоряют попытки записать `temp.json` по пути
`/mnt/vendor/mnt/vendor/persist/...`: hexagonrpcd раздаёт файлы только на
чтение, на работу датчиков это не влияет.

Установка: `install.sh` от root.

## Падение прокси при загрузке (27.09.2026)

После перезагрузки автоповорот не работал, потому что `iio-sensor-proxy`
упал с SIGSEGV через 14 секунд после старта. Падение было внутри
`ssc_sensor_compass_new_sync` (libssc). Синхронный поиск компаса крутит
главный цикл событий, и в это время в прокси приходит запрос KWin, а
прокси ещё не готов. Поиск затягивала сборка libssc 0.4.3-alt1.1 с моим
патчем повторного поиска (на компас он всё равно не помог, SLPI этого
датчика не отдаёт). Лечение такое:

- libssc откачена к версии Sisyphus 0.4.3-alt1
  (`apt-get install libssc=0.4.3-alt1 libssc-devel=0.4.3-alt1
  libssc-gir=0.4.3-alt1`, apt спрашивает подтверждение на откат);
- в drop-in прокси добавлен `Restart=on-failure`.

KWin к перезапущенному прокси сам не переподключается, ориентация остаётся
`undefined`. Будит его нажатие «Автоповорота» в быстрых настройках (вид
кнопки при этом не меняется, но автоповорот начинает работать).

## Компас (28.09.2026, работает)

SLPI не отдаёт готовый компас, но сырые магнитометр и акселерометр идут в
одной системе координат устройства (ориентация из реестра уже применена).
Проверено записью при вращении телефона во всех положениях:
- поправка на железо (сфера) около `-25 147 -25`, модуль поля 43-46 мкТл,
  разброс 1-3 мкТл;
- наклон поля к горизонту 68,4° (Москва, по таблицам около 70°);
- направление по формуле Android (`getRotationMatrix`) совпало со
  сторонами света, шаги по 90° при повороте телефона.

Драйвер компаса в iio-sensor-proxy переписан
(`packages/iio-sensor-proxy/iio-sensor-proxy-ssc-compass-mag.patch`,
выпуск 3.9-alt1.2):
- датчики открываются асинхронно: синхронные вызовы libssc крутят цикл
  событий, пока прокси ещё не готов;
- поправка на железо ищется на ходу вписыванием сферы в показания по 26
  направлениям и хранится в `/var/lib/iio-sensor-proxy/mag-calibration`
  (в drop-in `StateDirectory=iio-sensor-proxy`). Без файла компас молчит,
  пока телефон не повернут во все стороны;
- файл пишется и читается через `g_ascii_*`. Прокси работает с русской
  локалью, `sscanf("%lf")` не читал `-25.10`, калибровка не загружалась,
  и `ClaimCompass` не возвращался, потому что прокси отвечает на захват
  только после первого показания;
- направление магнитное, склонение в Москве около +11°.

Первая сборка (с ошибкой локали) дважды аппаратно выключила телефон: через
минуту после захвата компаса и потом при загрузке на 26-й секунде. Журнал
обрывается, pstore пуст, причина не установлена. Опытами исключены
сочетания датчиков libssc в одном процессе (акселерометр дважды,
магнитометр, свет, приближение, асинхронное открытие). Исправленная сборка
прошла ручной запуск с захватом на 2 минуты и перезагрузку с 3 минутами
наблюдения. Если сбой повторится, вернуть `/usr/libexec/iio-sensor-proxy.orig`.
Страховка на время перезагрузки: ждать появления телефона в сети и сразу
возвращать `.orig` (Wi‑Fi поднимается на ~22-й секунде, раньше прокси).
