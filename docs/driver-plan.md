# Загрузка калибровки голоса в ADSP: что есть в драйвере и что надо добавить

Цель: заставить работать топологии `TX_SM_ECNS_V2` (`0x00010f89`) и
`TX_DM_FLUENCE` (`0x00010f72`). Сейчас процессор отвечает `ADSP_EFAILED` на
`VSS_IVOCPROC_CMD_TOPOLOGY_COMMIT`, потому что для этих цепочек нужна
калибровка, а драйвер её не отправляет вовсе.

Откуда брать калибровку, разобрано полностью, см. `acdb-format.md`. Осталась
драйверная часть.

## Что в драйвере есть сегодня

Драйвер внемагистральный, автор Stephan Gerhold, в ALT входит как
`q6voice`. Файлы `q6voice.c`, `q6voice-common.c`, `q6mvm.c`, `q6cvp.c`,
`q6cvs.c`, `q6voice-dai.c`.

Разбор голосового тракта по файлам:

| Файл | Что делает |
|---|---|
| `q6voice.c` | связывает сессии, `q6voice_path_start` создаёт MVM и CVP, включает CVP, привязывает его к MVM, запускает голос |
| `q6mvm.c` | пассивная сессия MVM, двойное управление, привязка и отвязка vocproc, старт и стоп |
| `q6cvp.c` | создание сессии vocproc версий v2 и v3, число каналов, формат порта, `TOPOLOGY_COMMIT`, включение |
| `q6voice-common.c` | отправка команды APR и ожидание подтверждения, создание сессии, разбор ответов |

Порядок в `q6voice.c`, функция `session_create_v3`:

```
q6cvp_session_create_v3        VSS_IVOCPROC_CMD_CREATE_FULL_CONTROL_SESSION_V3
q6cvp_send_channel_info(rx)    VSS_ICOMMON_CMD_SET_PARAM_V2, VSS_PARAM_VOCPROC_RX_CHANNEL_INFO
q6cvp_send_channel_info(tx)    VSS_ICOMMON_CMD_SET_PARAM_V2, VSS_PARAM_VOCPROC_TX_CHANNEL_INFO
q6cvp_send_media_format(rx)    VSS_ICOMMON_CMD_SET_PARAM_V2, VSS_PARAM_RX_PORT_ENDPOINT_MEDIA_INFO
q6cvp_send_media_format(tx)    VSS_ICOMMON_CMD_SET_PARAM_V2, VSS_PARAM_TX_PORT_ENDPOINT_MEDIA_INFO
q6cvp_topology_commit          VSS_IVOCPROC_CMD_TOPOLOGY_COMMIT
```

Дальше `q6voice_path_start` делает `q6cvp_enable`, `q6mvm_attach`,
`q6mvm_start`.

Путь v3 выбирается по свойству дерева устройств `qcom,cvd-v2.3`, и именно его
отсутствие вызывало эхо: без свойства `TOPOLOGY_COMMIT` не отправлялся вовсе.

## Чего в драйвере нет

1. Разделяемой памяти с процессором. Ни одного обращения к `dma_alloc_*`, ни
   команд `VSS_IMEMORY_*`. Калибровку нельзя передать в теле команды APR, она
   не помещается: для пары устройств 4/7 один вариант это до 21 параметра и
   тысячи байт, а полный набор вариантов сотни килобайт.
2. Команд регистрации калибровки CVP, ни статической, ни динамической, ни
   громкостной, ни конфигурации устройства.
3. Любого источника самих данных калибровки. В заводской системе ACDB читает
   `libacdbloader` в пользовательском пространстве, здесь такого нет.

## Замысел

Разделение труда: разбор ACDB остаётся в пользовательском пространстве, ядро
получает готовый плоский блок параметров.

1. `tools/acdb.py export` выдаёт файл с параметрами одного варианта
   (заголовок `Q6VCAL01`, затем тройки «модуль, параметр, размер» и данные).
2. Драйвер читает этот файл через `request_firmware` и переносит параметры в
   буфер, отображённый процессору.
3. Отображение памяти командой `VSS_IMEMORY_CMD_MAP_PHYSICAL`, дескриптор
   приходит в ответе и хранится в сессии.
4. Регистрация калибровки командами CVP с указанием дескриптора памяти,
   адреса и размера.
5. Порядок вызовов внутри `session_create_v3`, точное место относительно
   `TOPOLOGY_COMMIT` берётся из порядка заводского драйвера.

Почему через `request_firmware`, а не разбором ACDB в ядре: формат
проприетарный, разбор нетривиальный, в ядро такое не примут, а для проверки
замысла файл прошивки достаточно положить в `/lib/firmware`.

## Что требует проверки до написания кода

- точные опкоды и структуры `VSS_IMEMORY_*` и команд регистрации калибровки;
- требования к выравниванию и к размеру блоков таблицы отображения;
- на какую сессию отправляется отображение памяти, MVM или CVP;
- место регистрации калибровки в последовательности настройки vocproc;
- раскладка блока калибровки в отображённой памяти, то есть что именно
  процессор ждёт по указанному адресу;
- умеет ли общий слой `q6voice-common.c` отдавать ответ с полезной нагрузкой,
  а не только подтверждение. Ответ на отображение памяти несёт дескриптор,
  и без этого его негде взять.

Эти пункты поднимаются по исходникам заводского драйвера, а не по памяти.
